# WebBundle 网页查包：总体架构与设计决策

> 状态：v1.3（按“离线查看属于单独挂载网页端”修正）
> 适用范围：BDS 26.x + LeviLamina + LegacyScriptEngine QuickJS
> 名称说明：`WebBundle` 是项目名称，指“网页查包套件”。
> 配套：[00 v1 范围与探针](00-v1范围与运行时探针.md) / [02 插件层](02-插件层与链入API.md) / [03 存储](03-数据模型与v1存储.md) / [04 网页层](04-网页层与HTTP契约.md) / [05 部署验收](05-部署运维与验收.md) / [07 单独挂载网页端](07-单独挂载网页端与离线修改.md) / [06 v2](06-v2-外部模式与分布式.md)

## 1. 这个工具解决什么问题

“查包”指管理员在浏览器里查看玩家背包、装备、副手、末影箱，查看物品**完整 NBT**，回溯历史备份，追踪物品来路，并在必要时修改背包、修改物品 NBT、还原历史背包。

现有 `Web-InvInspector` 验证了需求，但形态是“Node.js 单体插件 + 外部 Rust Web 服务 + SQLite”，有四个结构性问题：

| 现状 | 后果 |
|---|---|
| 插件层是约 3900 行的单文件 | 改一处要通读全文件；无法为单个规则写测试 |
| 只能外部启动 Web 服务 | 单机小服也要多维护一个进程和一套数据库 |
| 备份全量采集、查询走 SQLite 扫描 | 玩家多时 CPU 与 I/O 线性上涨 |
| 没有子模块契约、没有离线修改 | 第三方无法扩展；离线玩家改背包只能另写工具 |

WebBundle v1 的目标：

1. 插件用 QuickJS 编写，按领域拆分模块，核心规则可脱离 BDS 跑单元测试。
2. **插件内置网页**：BDS 运行时可用，开箱即用。
3. **单独挂载网页端**（`webbundle-web`，可选、独立部署）：接收插件推送的数据，BDS 停止后展示最后一次备份；**未部署就没有离线查看**。
4. 网页层只读；所有写操作以“动作意图”回到 qjs 插件，由世界线程执行并审计。
5. 提供缩小但稳定的链入 API，内置“网页指令执行”和“物品去向信息”两个模块。
6. 支持完整 NBT 查看/编辑、在线/离线玩家背包修改、历史背包还原。
7. 热路径不使用硬遍历：事件驱动影子状态，查询走索引与游标分页，备份按分钟桶合并。

“外部多服 / 分布式 / Redis/Mongo/Kafka / WebSocket / 多租户”是 v2，见 06；v1 的“单独挂载网页端”是单服独立部署，不是多服集群。

## 2. 设计约束（不可违反）

| 编号 | 约束 | 验收方式 |
|---|---|---|
| C1 | 世界线程只做轻量工作：事件回调内不序列化整包、不写盘、不发网络请求 | 代码审查 + tick 预算 |
| C2 | 内置网页 HTTP 处理器不触碰任何 BDS 对象 | 静态扫描 + 运行期断言 |
| C3 | 网页层没有写权限；写操作只能通过动作意图进入插件 | 路由表审查 + 读写端口分离 |
| C4 | 不使用硬遍历：请求路径不得遍历全部玩家/槽位/历史 | 查询计划审查 + 性能用例 |
| C5 | 跨分钟边界在线的玩家每分钟一个备份桶；同分钟幂等；崩溃不补历史桶 | 备份测试 |
| C6 | 在线背包变化到网页可见 p95 ≤1.5s；冷查看显示 `dataAsOf` | 端到端 |
| C7 | 没有 RocksDB 时，插件仍能以 Lite/LevelDB 分块索引降级启动 | 降级矩阵 |
| C8 | 代码 GPLv3-or-later；SPDX 头；注释使用正式技术表述，不出现对话式措辞 | 许可证/注释扫描 |
| C9 | 子模块只能通过链入 API；CI 扫描 import；qjs 同 realm，不是安全沙箱 | CI + 评审 |
| C10 | 配置、数据、模块 API 都有版本号与迁移路径 | 迁移测试 |
| C11 | v1 不实现多服/分布式/WS/多租户/第三方模块 | 范围审查 + 发布检查 |
| C12 | 内置网页只在 BDS 运行时可用；**离线查看只由单独挂载网页端提供** | 冷查看测试 |
| C13 | 未部署单独挂载网页端时，BDS 停止后**没有任何网页可用**；不提供兜底 | 边界测试 |
| C14 | 完整 NBT 不静默截断：小内联，大 `nbtRef`，超限拒绝 | NBT 测试 |
| C15 | 离线玩家修改可回滚、可审计、不能覆盖在线状态 | 离线读写/冲突测试 |

## 3. 运行时事实：已验证 vs 待探针

### 3.1 已验证

| 事实 | 影响 |
|---|---|
| QuickJS 支持 ES Module，入口相对导入以服务器工作目录为基准 | 入口写 `./plugins/WebBundle/...` |
| LSE 提供 `HttpServer`；回调在线程池执行并进入脚本引擎 | 内置网页可行；是否卡 tick 待探针 A |
| `HttpServer` 没有 WebSocket 服务端 | v1 轮询；WS 是 v2 |
| qjs 可以 `mc.listen`、`mc.runcmdEx`、`network.httpPost/httpGet`、`setTimeout` | 采集/异步推送可行 |
| qjs 没有 FFI、没有 zlib、没有 Node `crypto` | 本地存储用 KVDatabase/原生 sidecar；令牌待探针 D |
| `mc.getPlayerNbt(uuid)` / `mc.setPlayerNbt(uuid,nbt)` / `mc.setPlayerNbtTags(uuid,nbt,tags)` 存在 | 离线玩家读写可行（探针 F） |
| `data.xuid2uuid` / `data.name2uuid` / `data.getAllPlayerInfo` 存在 | xuid/name/uuid 映射 |
| `Item.getNbt()` / `Item.setNbt(nbt)` / `NBT.parseSNBT` / `NbtCompound.toSNBT` 存在 | 完整 NBT 查看/编辑（探针 E） |
| `onInventoryChange` / `onSetArmor` / `onTakeItem` / `onDropItem` 存在；无 `onCraftItem` | 影子状态/物品去向；合成推断 |

### 3.2 待探针

| 编号 | 问题 | 为什么不能假设 |
|---|---|---|
| A | 内置 `HttpServer` 回调是否卡 tick | 形态 A 的同步查存储边界 |
| B | `onInventoryChange` 是否逐槽/批量/漏触发 | 影子状态/物品去向准确性 |
| C | `listKey()` 成本 | 形态 A 本地历史索引 |
| D | 令牌随机性 | Web 令牌生成 |
| E | 完整 NBT 成本/大小 | 内联/ref/上限 |
| F | 离线 NBT 读写与冲突 | 离线修改是否可行 |
| G | 单独挂载网页端推送/冷查看/队列 | 离线查看与开服执行 |
| H | `webbundle-web` 静态+DB 并发 | 独立网页端稳定性 |

> 结论：**插件内置网页负责“BDS 运行时”；单独挂载网页端负责“BDS 停止后”。两者都不做对方的事。没有单独网页端就没有离线查看。**

## 4. v1 架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ BDS 进程                                                             │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │ qjs 插件                                                       │  │
│  │  事件适配器 → 影子状态 → 领域规则 → 本地存储/推送队列           │  │
│  │  内置 Web 适配器（LSE HttpServer，只读备份 + 动作）             │  │
│  │  动作执行器（在线/离线 NBT）                                    │  │
│  │  完整 NBT 捕获/写回                                             │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                    │ 可选：推送备份/事件/动作结果                    │
└────────────────────┼─────────────────────────────────────────────────┘
                     ▼
┌──────────────────────────────────────────────────────────────────────┐
│ webbundle-web（单独挂载，可选，独立进程/独立库）                        │
│  ├─ 网页 + /api/v1                                                    │
│  ├─ 自有数据库（SQLite/RocksDB/Mongo，按部署）                        │
│  ├─ 冷查看：BDS 停止后展示最后一次备份                                │
│  └─ 动作队列：BDS 关闭时的离线修改，开服后由插件拉取                  │
└──────────────────────────────────────────────────────────────────────┘

未部署 webbundle-web：BDS 停止后没有网页可用；这是预期行为，不是降级。
```

### 4.1 分层职责

| 层 | 职责 | 允许 | 禁止 |
|---|---|---|---|
| qjs 插件 | 事件采集、影子状态、完整 NBT、在线/离线写入、命令执行、审计 | 读写游戏状态；写本地存储；推送；轮询动作 | 在事件回调里写盘/发网络；把整包序列化放进世界线程 |
| 内置网页 | BDS 运行时的页面/API | 读备份/历史；提交动作 | 直接改背包/数据库；BDS 停止后仍被期望可用 |
| webbundle-web | 单独挂载的页面/API/冷查看/队列 | 读自己的库；接收推送；排队动作 | 直接调用游戏 API；直接改世界存档 |

### 4.2 依赖方向

```
内置 web ──▶ app（只读用例） ──▶ ports（读）
qjs 插件 ──▶ domain（纯规则） ──▶ ports（store/push/actions）
adapters/lse ──▶ 实现 ports
webbundle-web ──▶ 自己的 DB + 推送契约
```

- `domain/` 不 import `mc`、`ll`、`network`，可在 Node/qjs CLI 下测试。
- 内置网页代码不 import 写适配器；网页只读。

## 5. 两种形态

### 5.1 形态 A：插件内置网页（embedded）

- BDS 运行时由 qjs 启动 `HttpServer`。
- 静态资源、只读 API、动作都在插件进程内。
- 没有离线查看；BDS 停止即不可用。
- 适合单机、开箱即用、只看在线/本地历史。

### 5.2 形态 B：单独挂载网页端（external）

- `webbundle-web` 是独立进程/独立部署，自己有数据库。
- 插件通过 HTTP 推送备份/增量/事件/NBT/玩家元数据；`webbundle-web` 提供网页。
- BDS 停止后仍可看最后一次备份；这是离线查看的唯一来源。
- BDS 关闭时的离线修改进入 `webbundle-web` 队列；开服后插件拉取执行。
- **未部署/未运行 `webbundle-web`：没有离线查看，也没有 BDS 关闭时的离线修改队列。**

### 5.3 形态对照

| 能力 | 形态 A embedded | 形态 B external |
|---|---|---|
| 额外进程 | 无 | `webbundle-web` |
| 网页 | BDS 运行时 | 独立，BDS 停仍可看 |
| 冷查看 | 无 | 有（唯一来源） |
| 离线修改队列 | 无（BDS 停就没有网页） | 有 |
| 多服聚合 | 无 | v2（06） |
| 实时方式 | 轮询 | 轮询（v1）/WS（v2） |

> “插件内置网页启动”与“单独挂载网页端”是两件事；不要用前者承诺后者。

## 6. 关键数据流

### 6.1 实时背包

```
玩家操作 → onInventoryChange/onSetArmor/...（世界线程）
  → 影子状态 O(1) 更新 → 合并队列
  → 内置网页热缓存（形态 A）
  → 推送队列 → webbundle-web（形态 B，可选）
  → 网页轮询 /stream → patch
```

### 6.2 分钟备份

```
全局 1s tick → 分钟桶翻转
  → 跨分钟边界在线玩家入备份队列
  → 每 tick 预算 8 人/0.3ms
  → 序列化占用槽位 + NBT（小内联/大 ref）
  → 内容未变写引用；否则完整备份
  → 本地存储；形态 B 同时推送
```

### 6.3 读请求

形态 A：

```
浏览器 → 插件 HttpServer → 热缓存/本地存储 → 返回
BDS 停止：网页不可用
```

形态 B：

```
浏览器 → webbundle-web → 自有库 → 返回
BDS 停止：仍可读最后备份，dataAsOf + server.online=false
```

### 6.4 写请求

```
浏览器 → POST /api/v1/actions/*
  → 鉴权/校验/确认
  → 形态 A：插件动作队列
  → 形态 B：webbundle-web 动作队列
  → qjs 轮询（BDS 运行中）→ 世界线程执行 → 结果
  → BDS 关闭：形态 B 状态 queued_offline；开服后执行
```

### 6.5 在线/离线背包与 NBT

```
动作 inventory.edit / item.nbt.set / inventory.restore
  → 目标在线？
    ├─ 是：Player.getInventory()/getArmor()/getOffHand()/getEnderChest()
    └─ 否：data.xuid2uuid → mc.getPlayerNbt → 改 Inventory/Armor/Offhand/EnderChestInventory → mc.setPlayerNbtTags
  → 重新读取校验 → pre-edit 备份 → 更新影子 → 审计
```

### 6.6 完整 NBT

```
查看：小内联；大 nbtRef → /api/v1/nbt/<ref>
刷新：item.nbt.refresh → 世界线程读当前槽位 → 回写
编辑：item.nbt.set → NBT.parseSNBT → 校验 → 写回在线/离线 → 重读
```

## 7. 关键设计决策

### D1：qjs 承载业务，本地存储按形态选择

**决定**：插件层、规则、动作执行全在 qjs。形态 A 用 LSE `KVDatabase`/本地 sidecar；形态 B 由 `webbundle-web` 自己的数据库负责持久化。

**理由**：qjs 没有 FFI；形态 A 需要单进程开箱即用；形态 B 需要独立于 BDS 的生命周期。

### D2：两种形态，职责不重叠

**决定**：形态 A 只负责 BDS 运行时；形态 B 负责独立/离线查看。没有形态 B 就没有离线查看。v1 不把形态 B 强塞进插件进程，也不在形态 A 里假装能冷查看。

**理由**：用户明确离线查看是单独挂载网页端的功能；没有就不可用。

### D3：事件驱动影子状态

**决定**：进服一次种子；之后槽位事件增量；分钟备份序列化影子。

**风险**：探针 B；失败则对账，合成默认关闭。

### D4：网页只读，写操作走动作

**决定**：两种形态都没有直接写入口；所有写操作是 `Action`，由 qjs 世界线程执行。

### D5：模块 API 先缩小

**决定**：v1 只服务内置模块；去掉 `services`、模块 HTTP、`http.post`；第三方不开放。

### D6：完整 NBT 分级

**决定**：小 NBT 内联，大 NBT 走 `nbt` 列族 + `nbtRef`；单物品/单备份有上限；不静默截断。

### D7：离线修改走 NBT API

**决定**：BDS 运行时 `mc.getPlayerNbt`/`setPlayerNbtTags`；BDS 关闭时只有形态 B 能排队，开服后执行；不直接改世界存档。

### D8：审计单队列

**决定**：动作/命令完成事件进单一审计队列；有 `webbundle-web` 时由服务端代算 SHA-256；形态 A 用纯 JS 降级并限频。

### D9：GPLv3 与注释纪律进入 CI

**决定**：`GPL-3.0-or-later`；SPDX；注释使用正式技术表述，不出现对话式措辞。

### D10：探针先行

**决定**：A–H 没有结论之前不进 M1；失败先改设计/缩能力。

## 8. 质量目标

| 维度 | 目标 | 度量 |
|---|---|---|
| 正确性 | 影子状态与游戏内 99.9% 采样一致 | 漂移校正 + 测试 |
| 实时性 | 在线背包变化到网页 p95 ≤1.5s | 端到端 |
| 冷查看 | 形态 B 存在时可用；不存在时明确不可用 | G 测试 |
| 备份 | 跨分钟边界在线每分钟一个桶，覆盖率 100% | 备份指标 |
| NBT | 普通物品 NBT 查看 p95 ≤200ms；大 NBT 有 ref | NBT 测试 |
| 离线修改 | BDS 运行中成功；形态 B 队列开服执行成功 | F/G |
| 性能 | 事件 p99 ≤50µs；tick p99 ≤0.5ms | 基准 |
| 网页 | 本地读 p95 ≤10ms；静态不阻塞写 | H |
| 前端 | 1000 行实时 patch ≥60fps | M1 原型 |
| 安全 | 401/403/审计/令牌轮换 | 安全用例 |
| 可维护性 | 单文件 ≤400 行、单函数 ≤60 行；domain 覆盖率 ≥80% | CI |

## 9. 非目标与 v2

v1 不做：

- 多服聚合、分布式、Redis/Mongo/Cassandra/Kafka/冷归档；
- WebSocket/SSE；
- 第三方模块；
- 在 BDS 关闭时直接编辑世界存档（只排队）；
- 网络抓包/协议解析；
- 客户端 Mod/UI 注入；
- 跨服同步本身；
- **在未部署 `webbundle-web` 时提供任何离线查看兜底**。

v2 见 [06](06-v2-外部模式与分布式.md)。

## 10. 术语

| 术语 | 含义 |
|---|---|
| 形态 A / embedded | 插件内置网页；BDS 运行时可用 |
| 形态 B / external | 单独挂载网页端 `webbundle-web`；独立进程/库；离线查看唯一来源 |
| 冷查看 | BDS 停止后，形态 B 展示最后数据 |
| 备份 | 某时刻背包/装备/副手/末影箱内容（含 NBT） |
| 影子状态 | 插件内存中的背包镜像，由事件增量更新 |
| NBT ref | 大 NBT 的存储引用 |
| 动作 | 网页提交的受控写操作，由插件执行 |
| 硬遍历 | 请求/每 tick 遍历全部玩家/槽位/历史；本项目禁止 |

## 11. 决策清单

| 编号 | 决策 | 需要确认 |
|---|---|---|
| D1 | 形态 A 本地存储 + 形态 B 自有库 | 是否接受两套存储 |
| D2 | 离线查看只由形态 B 提供 | 未部署形态 B 就没有冷查看，是否确认 |
| D3 | 事件驱动影子状态 | 探针 B 失败时接受对账/合成关闭 |
| D4 | 网页只读 + 动作 | 是否接受所有写操作异步 |

# 容器地图与历史查看

> 状态：首版实现（未扫描未打开过的容器）
> 范围：WebBundle 内置端 + 独立网页端
> 依赖：BDS 容器事件、ZXDash 地图瓦片、现有物品快照/NBT 存储

---

## 1. 目标

把“玩家打开容器时看到的容器内容”变成可查询的地图数据：

- 玩家打开箱子/桶/漏斗/发射器/潜影盒等容器时，记录该容器位置、类型、完整内容和打开者。
- 在网页地图上按坐标显示容器和在线玩家。
- 点击容器直接查看内容，不需要先进入玩家背包。
- 很近或同坐标的容器在地图上合并为一个点。
- 点击合并点后，按坐标生成 3D 容器视图，可逐个打开查看。
- 支持按日期/时间查看历史：
  - 当天出现过的容器都能在地图上看到
  - 查看某个时间点的容器内容
  - 已挖掉的容器实时消失，但历史仍保留
- 支持所有有容器的方块，而不只是箱子。
- 容器里的嵌套容器内容也要能看到。

---

## 2. 范围与假设

### 2.1 首版范围

- 地图底图读取 ZXDash 已生成的 Unmined 瓦片。
- 玩家位置显示实时在线位置。
- 容器来源以 **玩家打开/关闭容器** 为主，辅以容器内容变化事件。
- 容器历史按天存储，支持时间点回看。
- 地图容器内容只展示“已观测到的容器”。

### 2.2 需要明确的假设

首版 **不主动扫描全地图未打开过的容器**。原因：

- 全图方块扫描开销大，会与 ZXDash 渲染争主线程。
- 需求起点是“玩家开启箱子的时候存储”。

因此：

- “所有容器”指所有 **支持的类型**：箱子、陷阱箱、桶、潜影盒、发射器、投掷器、漏斗、熔炉、高炉、烟熏炉、酿造台、工作台等有 `hasContainer()` 的方块。
- 未打开过的容器要显示，需要额外做“已加载区块容器扫描”，列为后续可选能力。

### 2.3 不做

- 不在首版修改 ZXDash 的 DLL 或地图渲染代码。
- 不把容器内容直接写进地图瓦片 PNG。
- 不在列表接口返回完整 NBT。
- 不允许通过地图接口修改容器内容。
- 不做跨服容器同步。

## 3. 用户流程

### 3.1 实时地图

1. 玩家打开箱子。
2. WebBundle 记录容器位置和打开时内容。
3. 地图上出现容器标记。
4. 点击标记：
   - 单容器：打开内容抽屉。
   - 合并点：打开 3D 容器视图。
5. 玩家挖掉箱子：
   - 实时地图立即隐藏该标记。
   - 历史模式仍能看到。

### 3.2 历史查看

1. 地图切到“历史”。
2. 选择日期和具体时间。
3. 地图显示当天出现过的容器：
   - 仍在：正常标记
   - 当天已挖掉：删除态标记
   - 当天才出现：正常标记
4. 点击容器查看该时间点最近一次观测内容。
5. 点击“打开记录”查看该容器当天所有打开/关闭事件。

### 3.3 合并点 / 3D 视图

1. 地图缩放较远，附近容器合并为 `×N` 标记。
2. 点击合并点，打开 3D 容器场景。
3. 每个容器按照实际相对坐标摆放。
4. 点击 3D 容器，右侧打开该容器内容。
5. 关闭内容后回到 3D 场景。

## 4. 数据模型

### 4.1 容器主记录

位置是容器的主键：

```text
container:<dim>:<x>:<y>:<z>
```

示例：

```text
container:0:120:64:-380
```

字段：

```json
{
  "schema": 1,
  "id": "container:0:120:64:-380",
  "dim": 0,
  "x": 120,
  "y": 64,
  "z": -380,
  "type": "minecraft:chest",
  "name": "箱子",
  "generation": 1,
  "firstSeen": 1790000000000,
  "lastSeen": 1790000400000,
  "removedAt": 0,
  "state": "present",
  "currentObservationId": "obs-...",
  "currentItemCount": 27,
  "currentContainerCounts": {
    "inventory": 27,
    "armor": 0,
    "offhand": 0,
    "ender": 0
  },
  "lastPlayer": {
    "xuid": "2535...",
    "name": "Player"
  },
  "linkedPos": null,
  "dayKeys": ["2026-10-26"]
}
```

- `generation`：同坐标容器被替换/重新放置时递增。
- `linkedPos`：双箱子另一半坐标，用于合并/避免重复标记。
- `removedAt`：0 表示当前仍在。
- `state`：`present` / `removed` / `unknown`。

### 4.2 观测记录

每次打开/关闭/内容变化生成一条观测：

```text
container:obs:<observationId>
```

```json
{
  "schema": 1,
  "id": "obs-...",
  "containerId": "container:0:120:64:-380",
  "at": 1790000000000,
  "reason": "open",
  "player": {"xuid": "...", "name": "..."},
  "type": "minecraft:chest",
  "dim": 0,
  "x": 120,
  "y": 64,
  "z": -380,
  "size": 27,
  "items": [
    {
      "slot": 0,
      "item": {
        "t": "minecraft:shulker_box",
        "c": 1,
        "meta": {
          "containerItems": []
        }
      }
    }
  ],
  "itemCount": 27,
  "containerCounts": {},
  "contentHash": "fnv1a...",
  "nbtRefs": {}
}
```

- `items` 使用现有 `serializeItem(item, { full: true })` 输出。
- `meta.containerItems` 继续复用现有嵌套结构。
- 大 NBT 继续走 `nbt:<hash>` 引用，不重复写。
- 同一容器内容没有变化时，只写索引引用，不重复写完整内容。

### 4.3 日索引

```text
container:day:<YYYY-MM-DD>
```

存当天出现/被观测过的容器 ID 列表。

用途：

- 历史模式查询“整个当天出现过的箱子”。
- 避免按全量容器索引扫描。

### 4.4 空间索引

为了地图 bbox 查询，使用网格桶：

```text
container:grid:<dim>:<gx>:<gz>
```

- 默认 16×16 区块为一个桶，或按 256×256 方块分桶。
- 容器首次观测/位置变化时写入。
- 查询地图视野时只读覆盖的桶。
- 容器移除后从当前桶移除，但日索引和历史记录保留。

### 4.5 容器内容版本

```text
container:state:<observationId>
```

存单个观测的完整内容。

- 当前内容指针在容器主记录的 `currentObservationId`。
- 历史时间点查询时，取 `at <= 目标时间` 的最近一条观测。
- 相同 `contentHash` 的内容只保留一个内容对象，多个观测引用它。

## 5. 采集

### 5.1 打开容器

使用 LSE 事件：

```js
mc.listen("onOpenContainer", (player, block) => {
  // block.pos / block.type / block.hasContainer()
  // block.getContainer()
});
```

步骤：

1. 校验 `block`、`block.pos`、`block.hasContainer()`。
2. 取 `ct = block.getContainer()`。
3. 读 `ct.size`，逐个 `ct.getItem(i)`。
4. 使用 `serializeItem` 保存完整物品与嵌套内容。
5. 计算内容哈希。
6. upsert 容器主记录。
7. 生成 `open` 观测。
8. 更新日索引、空间索引。
9. 推送到独立端。

### 5.2 关闭容器

监听：

```js
mc.listen("onCloseContainer", (player, block) => { ... });
```

用途：

- 记录关闭时内容（`reason=close`）。
- 让“打开期间发生的修改”有一个最终状态。
- 不覆盖打开时观测，历史保留两个时间点。

### 5.3 容器内容变化

监听：

```js
mc.listen("onContainerChange", (player, container, slot, oldItem, newItem) => { ... });
```

用途：

- 对已观测容器更新当前内容。
- 对尚未观测的容器补建记录。
- 做 500ms 防抖，避免一格一格写盘。

### 5.4 容器被挖掉/替换

监听：

```js
mc.listen("onBlockChanged", (beforeBlock, afterBlock) => { ... });
```

- `beforeBlock` 有容器，`afterBlock` 没有容器：
  - `removedAt = now`
  - `state = removed`
  - 从当前空间索引移除
- 同坐标换成另一个容器：
  - 旧记录标记 removed
  - 新建 `generation + 1` 的容器记录

### 5.5 双箱子

`onOpenContainer` 只给出一半位置时：

- 检查相邻 `±1` 的 X/Z 方块是否为同类箱子。
- 取坐标较小的一侧作为主坐标。
- 记录 `linkedPos`。
- 地图只画一个合并标记，不重复计数。

### 5.6 容器类型

不写死箱子列表。使用：

```js
block.hasContainer()
block.getContainer()
```

同时保留 `block.type` 白名单做兜底和显示名映射：

```text
minecraft:chest
minecraft:trapped_chest
minecraft:barrel
minecraft:shulker_box
minecraft:undyed_shulker_box
minecraft:dispenser
minecraft:dropper
minecraft:hopper
minecraft:furnace
minecraft:blast_furnace
minecraft:smoker
minecraft:brewing_stand
minecraft:enchanting_table
...
```

### 5.7 嵌套容器

沿用现有物品序列化：

```text
item.meta.containerItems[]
```

- 递归读取，最大深度默认 3。
- 最大嵌套项数默认 256/层。
- 超出时记录 `nestedTruncated: true`。
- 潜影盒里的潜影盒继续显示到下一层。

## 6. 地图

### 6.1 底图来源

ZXDash 生成的地图瓦片：

```text
plugins/ZXDash/unmined-web/tiles/<dim>/<zoom>/<tileX>_<tileY>.png
plugins/ZXDash/unmined-web/region_info.json
plugins/ZXDash/map_config.json
```

读取：

- `map_config.json` 的 `zoomIn` / `zoomOut` / `lastRender`
- 瓦片目录
- 维度目录（当前已知 `overworld`，其余维度按实际目录探测）

WebBundle 不重新渲染地形，只做：

- 瓦片代理
- 坐标投影
- 容器/玩家标记叠加
- 点击/聚合交互

### 6.2 瓦片代理

BDS 内置端：

```http
GET /api/v1/map/tiles/:dim/:zoom/:tx/:ty
```

返回对应 PNG，带缓存头。

独立端：

- 读取服务器目录中的同一份 ZXDash 瓦片。
- BDS 停止后仍能看历史地图。

### 6.3 坐标投影

需要一个独立适配层：

```text
worldToTile(x, z, zoom) -> { tx, ty, px, py }
tileToWorld(tx, ty, zoom) -> { x, z }
```

要求：

- 用 ZXDash 实际瓦片做校准。
- 不把投影公式散落在前端各处。
- 容器和玩家共用同一投影。

### 6.4 地图图层

- 地形瓦片
- 容器层
- 玩家层
- 合并点层
- 选中态/历史删除态

### 6.5 玩家位置

实时：

- 来自 `mc.getOnlinePlayers()` 的 `xuid/name/pos.dimid/pos`。
- 1 秒轮询。

历史：

- 使用快照中的 `pos` 或容器观测时记录的玩家位置。
- 历史玩家位置只做辅助显示，不作为精确轨迹。

### 6.6 容器标记

列表接口只返回摘要，不返回完整内容：

```json
{
  "id": "container:0:120:64:-380",
  "dim": 0,
  "x": 120,
  "y": 64,
  "z": -380,
  "type": "minecraft:chest",
  "itemCount": 27,
  "state": "present",
  "preview": [
    {"t": "minecraft:diamond", "n": "钻石", "c": 64}
  ],
  "previewMore": 5,
  "clusterId": "..."
}
```

点击后再取完整内容。

## 7. 聚合与 3D 视图

### 7.1 聚合规则

同一维度内：

1. 先按实际坐标合并：
   - 同坐标多代容器 → 垂直堆叠
   - 双箱子 → 一个主点
2. 再做邻近聚合：
   - 默认距离 `clusterRadius = 4` 方块
   - 可用配置调整
3. 地图缩小时做屏幕空间聚合：
   - 屏幕距离低于阈值（例如 18px）合并
4. 聚合点显示：
   - 数量
   - 地图最多显示 100 个标点，按视野中心优先最近
   - 最近容器类型
   - 是否有删除态

聚合不跨维度，不跨超过阈值的独立基地。

### 7.2 合并点点击

返回聚合内所有容器：

```json
{
  "clusterId": "...",
  "dim": 0,
  "center": {"x": 120, "y": 64, "z": -380},
  "count": 6,
  "containers": [
    {"id": "...", "x": 120, "y": 64, "z": -380, "type": "minecraft:chest"}
  ]
}
```

### 7.3 3D 视图

当前实现使用 **本地打包 Three.js**，按 3 格间距自动分层：

- 每个容器画成有顶面/正面/侧面的立方体。
- 按真实相对坐标摆放，比例可缩放。
- 支持拖拽旋转、滚轮缩放；前后左右或垂直间距超过 3 格时自动分成独立层。
- 同坐标容器按 Y 轴叠放。
- 点击立方体打开内容抽屉。
- 已删除容器用半透明/描边显示（历史模式）。
- 容器数量过多时：
  - 只渲染视口内
  - 远处用小方块/点
  - 提供列表兜底

不使用 Three.js 作为首版硬依赖；如果后续需要自由轨道视角，再评估打包本地 Three.js。

### 7.4 内容抽屉

点击 3D 容器后：

- 右侧抽屉默认进入“容器内容”页。
- 显示容器类型、坐标、观测时间、打开者。
- 物品网格复用现有 `mc-grid` / nested 渲染。
- 嵌套容器可继续点开。

## 8. 历史

### 8.1 两种模式

```text
realtime：当前仍存在的容器
history：指定日期 + 指定时间点
```

### 8.2 历史查询语义

选择日期 `D` 和时间点 `T`：

1. 从 `container:day:D` 取当天出现过的容器。
2. 过滤：
   - `firstSeen <= D 23:59:59`
   - `removedAt == 0` 或 `removedAt >= D 00:00:00`
3. 对每个容器取 `at <= T` 的最近观测。
4. 没有早于 T 的观测时，取当天第一条观测并标记 `unknownAtT`。

显示状态：

- `present`：T 时刻仍在
- `removed`：T 时刻已删除
- `unknown`：当天有记录，但 T 之前没有观测
- `changed`：T 之后内容发生改变

### 8.3 当天全部出现过的容器

历史模式的地图点集合是：

> 当天任意时刻出现过的容器，而不是只显示 T 时刻仍存在的容器。

因此：

- 早上出现、下午被挖掉的箱子，在晚上查看历史时仍显示。
- 实时模式不显示它。

### 8.4 时间轴

容器详情提供：

- 当天打开/关闭/变化事件列表
- 每个事件的时间、玩家、物品数
- 点击事件跳到该内容版本

### 8.5 保留时间

建议：

```text
container.retentionDays = 90
```

- 当前容器主记录：永久保留到容器被替换/清除
- 观测内容：默认 90 天
- 日索引：保留 180 天
- 超过保留期只保留日摘要（位置、类型、打开次数），不保留完整内容

该值可配置，最终数值待确认。

## 9. 接口草案

### 9.1 地图元信息

```http
GET /api/v1/map/meta
```

返回：

```json
{
  "tileUrl": "/api/v1/map/tiles/{dim}/{zoom}/{tx}/{ty}",
  "zoomIn": 2,
  "zoomOut": -7,
  "lastRender": 1790000000000,
  "dimensions": ["overworld"],
  "clusterRadius": 4,
  "retentionDays": 90
}
```

### 9.2 地图容器

```http
GET /api/v1/map/containers
```

参数：

```text
dim
from / to
at
day
bbox=minX,minZ,maxX,maxZ
zoom
cluster=0|1
```

返回聚合点或容器摘要；不返回完整 NBT。

### 9.3 聚合详情

```http
GET /api/v1/map/clusters/:id
```

### 9.4 容器详情

```http
GET /api/v1/containers/:id
GET /api/v1/containers/:id?at=...
```

返回容器、当前/指定时间内容、嵌套物品。

### 9.5 容器历史

```http
GET /api/v1/containers/:id/history?day=2026-10-26
```

返回当天观测列表。

### 9.6 玩家位置

```http
GET /api/v1/map/players
```

### 9.7 瓦片

```http
GET /api/v1/map/tiles/:dim/:zoom/:tx/:ty
```

### 9.8 权限

新增权限：

```text
map.read
container.read
container.history
```

默认：

- viewer：`map.read`、`container.read`、`container.history`
- 内容详情可以继续复用 `inventory.read`

## 10. 独立端

独立端需要同步：

- 容器主记录
- 观测内容
- 日索引/空间索引

推送接口：

```http
POST /push/v1/container
```

- 按容器 ID upsert。
- 观测内容可分条推送。
- NBT 引用继续走 `nbtRefs`。
- BDS 停止后独立端可查看历史和最后内容。

独立端地图瓦片：

- 如果同机部署，直接读 `plugins/ZXDash/unmined-web/`。
- 如果分开部署，复制/挂载地图目录，配置路径。
- 没有 ZXDash 瓦片时，地图底图显示占位，但容器列表/详情仍可查。

- 地图占满屏幕
- 容器内容用底部抽屉
- 3D 视图全屏

## 12. 查包容器抽屉

这是独立于地图的另一处改动：

### 12.1 默认打开容器内容

当查包页打开一个带 `meta.containerItems` 的物品时：

- 抽屉默认激活“容器”页，而不是“详情”页。
- 没有内容但类型是潜影盒时，显示空容器而不是隐藏入口。

### 12.2 悬浮查看内容

容器格子/地图标记悬浮时显示：

- 容器类型
- 前 5 件物品图标 + 名称 + 数量
- 剩余件数
- 嵌套容器标记

不一次性渲染全部内容，避免大容器卡顿。

## 13. 性能与存储

### 13.1 控件

- 地图接口只按 bbox/zoom 返回聚合摘要。
- 完整内容点击后才加载。
- 容器观测按内容哈希去重。
- NBT 走引用。
- 容器内容变化 500ms 防抖。
- 地图玩家轮询 1s，容器摘要轮询 5s。
- 3D 视图只渲染视口内。

### 13.2 规模估算

单容器一次观测：

- 普通箱子：几 KB
- 装满潜影盒：几十 KB
- 大 NBT：引用后只存哈希

建议单服首版上限：

```text
容器主记录：100000
观测记录：30 天 / 可配置
单次接口摘要：最多 500 个聚合点
```

### 13.3 不应做的事

- 不在 tick 内做容器扫描。
- 不在容器打开事件里同步写大 JSON 文件。
- 不把完整容器内容塞进地图标记接口。
- 不在每次地图拖动时全量查库。

## 14. 验收标准

1. 打开箱子后 1 秒内地图出现容器。
2. 点击单容器能直接看到内容。
3. 邻近/重叠容器合并为一个点。
4. 合并点能打开 3D 视图，逐个容器可打开。
5. 挖掉箱子后实时地图消失，历史地图仍显示。
6. 历史日期能看到当天出现过的所有已观测容器。
7. 历史时间点能还原该容器当时内容。
8. 漏斗、发射器、投掷器、潜影盒等都能记录。
9. 潜影盒内物品/嵌套潜影盒可查看。
10. 查包容器默认打开容器页。
11. 容器格子悬浮能看到内部物品预览。
12. 独立端在 BDS 停止后仍能查看历史和内容。
13. 地图接口不返回完整 NBT。
14. 容器标记数量多时仍可拖动/缩放。

## 16. 待确认

1. 未打开过的容器是否也要全图扫描？
   - 首版不做，只显示已观测容器。
2. 容器历史保留多久？
   - 建议 90 天，观测内容 90 天，日索引 180 天。
3. 3D 视图是否必须支持自由轨道旋转？
   - 首版等距投影 + 90° 旋转；如必须真 3D，需评估打包 Three.js。
4. 地图底图是否直接嵌 ZXDash 页面，还是独立 Canvas 叠加？
   - 首版独立 Canvas，读 ZXDash 瓦片，便于叠加容器。
5. 容器内容变化是否要记录每一次格子变化？
   - 建议只记录打开/关闭和 500ms 防抖后的最终内容，避免刷爆存储。
6. 双箱子/大箱子如何归一化？
   - 已按相邻方块合并，具体实现需在真实世界验证。
7. 历史全部玩家位置还是只在线位置？
   - 首版实时在线 + 快照位置辅助。
8. 地图瓦片目录在独立端如何挂载？
   - 同机直接读；分机需配置复制/共享路径。

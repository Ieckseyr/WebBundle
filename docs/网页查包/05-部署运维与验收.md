# WebBundle v1 部署运维与验收

> 状态：v1.3（两种网页形态；离线查看属于单独挂载网页端）
> 上游：[00 v1 范围](00-v1范围与运行时探针.md) / [01 总体架构](01-总体架构与设计决策.md) / [02 插件层](02-插件层与链入API.md) / [03 存储](03-数据模型与v1存储.md) / [04 网页层](04-网页层与HTTP契约.md) / [07 单独挂载网页端](07-单独挂载网页端与离线修改.md)
> **形态 A：插件内置网页，BDS 运行时可用。形态 B：单独挂载 `webbundle-web`，可选；未部署它，BDS 停止后就没有任何网页可用。** 外部多服/分布式是 v2（06）。

---

## 1. 部署形态

| 形态 | 组件 | BDS 停止后 | 离线修改队列 | 适用 |
|---|---|---|---|---|
| A 内置 | BDS + qjs 插件（+ 可选本地侧车） | **网页不可用** | 无 | 单机、开箱即用 |
| B 单独挂载 | A + `webbundle-web`（独立进程/独立库） | 冷查看 | 有 | 需要 BDS 停止后仍能查/改 |
| B 未部署 | 只有 A | **无网页** | 无 | 预期边界，不是降级 |

> BDS 离线查看是形态 B 的功能；没有 `webbundle-web` 就完全不可用，没有兜底。

### 1.1 端口

| 端口 | 组件 | 默认 | 说明 |
|---|---|---|---|
| 19380 | 插件内置 Web（形态 A） | `127.0.0.1` | BDS 运行时 |
| 8080 | `webbundle-web`（形态 B） | `127.0.0.1` | 独立部署；反向代理 |
| 19381 | 本地存储侧车（可选） | `127.0.0.1` | 形态 A |

### 1.2 目录

```
<server>/
├── plugins/WebBundle/             qjs 插件
├── plugins/WebBundle/data/                 插件本地数据
│   ├── config.json
│   ├── logs/
│   ├── store/                   RocksDB（可选侧车）
│   └── leveldb/                 Lite
└── webbundle-web/                 单独挂载网页端（可部署在别处）
    ├── data/                    自有库
    └── public/                  dist
```

### 2.2 单独挂载网页端配置

```json
{
  "listen": "127.0.0.1:8080",
  "publicUrl": "https://panel.example.com",
  "db": { "driver": "sqlite", "path": "./data/webbundle.db" },
  "web": { "tokenHash": "" },
  "push": { "tokens": [] },
  "cors": { "allowOrigins": ["https://panel.example.com"] },
  "nbt": { "inlineMaxKB": 64, "itemMaxKB": 512, "snapshotMaxMB": 8 },
  "actions": { "offlineTtlHours": 24 }
}
```

### 2.3 配置规则

- 未知键告警不删除；类型错误回落默认值。
- `_config_version` 迁移；迁移前备份。
- 敏感值：形态 A 的 `web.tokenHash` 只存 `sha256:<hex>`；形态 B 的浏览器密码只存 PBKDF2-SHA256 哈希 + 盐，不存明文；`pushToken` 是机器共享密钥，插件侧需明文发送，限制文件权限/环境变量，禁止写日志。
- `serverId` 自动生成；字符集 `^[A-Za-z0-9_-]{1,64}$`，不能含冒号。
- `backup.intervalSec` 默认 60；改动属于产品变更。
- `flow.inferCraft` 默认 false；合成实验性。
- `push.enabled=false`：不推送、无冷查看；这是形态 A 的正常配置。

## 3. 安装

### 3.1 形态 A：插件 + 内置网页

1. 解压到 `plugins/WebBundle/`。
2. 启动 BDS；插件生成 `plugins/WebBundle/data/config.json`，打印 Web 令牌一次。
3. 访问 `http://127.0.0.1:19380`。
4. BDS 停止后网页不可用（预期）。

### 3.2 形态 B：单独挂载网页端

1. 部署 `webbundle-web`（本机或另一台机器），配置 `db`/`pushToken`；首次用本机浏览器打开 `/setup` 创建管理员账号。
2. 反向代理 + TLS 暴露 `webbundle-web`；首次设置完成后再开放公网。
3. 在插件配置中设置：

```json
"external": {
  "enabled": true,
  "url": "https://panel.example.com",
  "token": "<pushToken>",
  "pollSec": 2
}
```

4. 重启 BDS；插件推送；`webbundle-web` 显示服务器上线。
5. 停止 BDS，刷新 `webbundle-web`：显示 `server.online=false`、`dataAsOf`、最后备份。

### 3.3 本地侧车（可选，形态 A）

如果希望形态 A 有更好的本地历史查询，可安装 `webbundle-store` 侧车（RocksDB）；不装则用 LevelDB 分块索引。

### 3.4 首次验收

1. 在线背包/装备/副手可见；变化 ≤1.5s。
2. 物品详情完整 NBT；大 NBT 单独加载。
3. 停止 BDS：形态 A 不可用；形态 B 可看最后数据。
4. **不启动形态 B**：BDS 停止后确认没有网页可看。
5. 形态 B 中提交离线修改，开服后执行。
6. 审计记录。

## 4. 反向代理

**Caddy**：

```caddyfile
panel.example.com {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8080
    header {
        X-Content-Type-Options nosniff
        Referrer-Policy no-referrer
        X-Frame-Options DENY
        -Server
    }
}
```

**Nginx**：

```nginx
server {
    listen 443 ssl http2;
    server_name panel.example.com;

    ssl_certificate     /etc/ssl/panel.crt;
    ssl_certificate_key /etc/ssl/panel.key;

    client_max_body_size 2m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

- 形态 A 的 19380 只在 BDS 运行时有用；不要把侧车 19381 暴露公网。
- `trustProxy` 只在确认只有反向代理能访问时开启。

## 5. 启动、关闭与故障

### 5.1 启动顺序

形态 A：

```
BDS → qjs 插件 → 内置 HttpServer → 页面
```

形态 B：

```
webbundle-web（可先启动）→ BDS → 插件推送/轮询 → 页面
```

### 5.2 关闭

- BDS 停止：形态 A 页面消失；形态 B 继续冷查看；动作排队。
- `webbundle-web` 停止：形态 B 不可用；形态 A 不受影响；插件 spool。
- 两者都停：只有 BDS 本地数据，没有网页。

### 5.3 常见故障

| 现象 | 排查 |
|---|---|
| 形态 A 打不开 | BDS 是否运行；19380；插件日志 |
| BDS 停止后打不开 | 是否部署/启动形态 B（预期：没部署就没有） |
| 形态 B 401 | 是否已完成 `/setup`、是否登录、会话是否过期 |
| 背包不更新 | 插件推送；`onInventoryChange`（探针 B） |
| 完整 NBT 不显示 | 是否捕获；大 NBT ref 404；探针 E |
| 离线修改失败 | uuid 是否存在；`setPlayerNbtTags`；玩家在线冲突 |
| 开服队列不执行 | 插件是否拉取；任务过期；目标在线 |
| 审计断链 | 并发/磁盘；`/audit/verify` |

## 6. 升级、迁移与回滚

1. 备份 `plugins/WebBundle/data/` 与 `webbundle-web` 的库。
2. 停 BDS；`webbundle-web` 可保持运行。
3. 替换插件与 `webbundle-web`；保留数据目录。
4. 运行迁移；检查 schema。
5. 启动 BDS；验证形态 A、推送、形态 B 冷查看/队列。
6. 观察 30 分钟。

回滚：保留上一版与数据库备份；schema 升级后不自动降级。

从 Web-InvInspector 迁移：备份/事件/命令历史；NBT 缺失标 `nbtOmitted=true`；无 uuid 的玩家跳过离线修改。

## 7. 备份与灾难恢复

| 数据 | 位置 | 频率 |
|---|---|---|
| 插件本地存储 | `plugins/WebBundle/data/store` / `leveldb` | 每天 |
| `webbundle-web` 库 | `webbundle-web/data` | 每天 |
| 配置 | 两处 | 每次变更 |
| 审计 | 导出 NDJSON | 每天 |

恢复：

1. 停 BDS/网页端。
2. 恢复本地库与网页端库到新目录。
3. 恢复配置；确认 `serverId`。
4. 启动 BDS → 形态 A；启动 `webbundle-web` → 冷查看。
5. 检查推送续传、操作记录链、离线队列。

RPO ≤1 分钟；RTO ≤30 分钟；审计 ≥180 天。

## 8. 可观测性

### 8.1 指标

| 指标 | 说明 |
|---|---|
| `webbundle_events_total` | 事件 |
| `webbundle_tick_budget_ms` | tick 开销 |
| `webbundle_backup_lag_seconds` | 备份延迟 |
| `webbundle_push_queue_depth` | 推送队列 |
| `webbundle_push_errors_total` | 推送失败 |
| `webbundle_http_request_seconds` | 形态 A/B |
| `webbundle_nbt_capture_seconds` | NBT 捕获 |
| `webbundle_offline_apply_seconds` | 离线写入 |
| `webbundle_audit_chain_breaks` | 审计断链 |

### 8.2 告警

- 备份落后 >2 分钟；
- 推送队列 >1000；
- 形态 B 超过 5 分钟没收到心跳（BDS 在线时）；
- 审计断链/积压；
- 磁盘 <15%；
- 离线任务失败率 >5%。

### 8.3 健康检查

- 形态 A：`/healthz`（BDS 运行时）。
- 形态 B：`/healthz`、`/api/v1/health`（`server.online`、库、队列）。
- 插件日志：注册/推送/动作/离线写入。

## 9. 性能与容量

### 9.1 预算

| 项 | 目标 |
|---|---|
| 每 tick 插件开销 | p99 ≤0.5ms |
| 事件回调 | p99 ≤50µs |
| 分钟备份 | 8 人/tick，≤0.3ms |
| 形态 A Web | p95 ≤10ms（探针 A） |
| 形态 B 读 | p95 ≤50ms |
| 冷查看首屏 | p95 ≤300ms |
| NBT 单物品读取 | p99 ≤5ms |
| NBT SNBT | p99 ≤10ms |
| 离线 NBT 写入 | p99 ≤50ms |
| 前端 1000 行实时 patch | ≥60fps |

### 9.2 容量

100 在线/30 天：约 10–15GB/月（含 NBT），详见 03 §8.1。两套库（本地 + 网页端）各自规划磁盘；网页端可按保留期裁剪。

### 9.3 压测

1. 500 玩家 ×2 次槽位变化/秒 ×10 分钟。
2. 100 玩家分钟备份 + 20% 变化 + 带 NBT 物品。
3. 形态 B 冷查看并发 + 推送写入。
4. 推送停止 30 秒恢复，spool 续传。
5. 离线修改队列 100 条，开服执行。

## 10. 安全

- 形态 A 默认只监听回环；公网经反向代理 + TLS。
- 形态 B 独立部署，强制 HTTPS；`pushToken` 与 Web 令牌分离。
- Web 令牌只存哈希；`sessionStorage`。
- 完整 NBT 可能含敏感文本；按 `inventory.read`，不写日志。
- 离线修改：`inventory.write` + 确认 + pre-edit 备份 + 审计；默认 admin。
- 冷查看也鉴权；不因 BDS 停止放宽。
- 不在 `webbundle-web` 直接改世界存档。
- 依赖许可证清单；GPLv3 源码可得。

## 11. 验收

### 11.1 功能

1. 形态 A：BDS 运行时背包/装备/副手可见；BDS 停止后不可用。

## 12. 里程碑（v1.3）

### M0：探针 A–H（3–5 天）

- 内置 HttpServer、onInventoryChange、listKey、令牌、NBT、离线 NBT、形态 B 冷查看/队列、网页端并发。
- 退出：八项有结论；架构假设有降级。

### M1：形态 A + 采集 + 备份 + 只读页（2–3 周）

- 插件内置 Web、本地存储、影子状态、分钟备份、只读页。
- 前端原型 60fps。
- 退出：BDS 运行时可用；备份覆盖率 100%；tick 达标。

### M2：完整 NBT + 在线/离线修改 + 形态 B（2–3 周）

- NBT 捕获/ref/查看/编辑；在线/离线写入；pre-edit/审计。
- `webbundle-web` 部署、推送、冷查看、离线队列。
- 退出：形态 B 冷查看/队列/开服执行；未部署时明确无冷查看。

### M3：指令 + 物品去向（2 周）

- 命令白名单/队列/审计；丢弃/拾取；实验性合成。
- 退出：安全用例；物品去向无双计；unknown 明示。

### M4：加固与发布（1–2 周）

- 性能/混沌/安全；文档；GPLv3。
- 退出：A/B 安装；冷查看/离线修改/恢复演练；发布检查。

v2 多服/分布式另立里程碑。

## 13. 风险

| 风险 | 对策 |
|---|---|
| 用户误以为插件自带离线查看 | 文档/页面明确：形态 B 才提供；未部署就没有 |
| 形态 B 运维成本 | 独立部署是可选的；不部署就只用形态 A |
| qjs 内置 Web 卡 tick | 探针 A；只读内存/异步查询 |
| 事件语义不可靠 | 探针 B；对账；合成关闭 |
| 完整 NBT 撑爆 | 小内联/大 ref/上限；探针 E |
| 离线 NBT 写入被缓存/登录覆盖 | 探针 F；前后检查在线；冲突失败 |
| 离线修改直接改存档风险 | v1 不做；只排队 |
| 模块 API 膨胀 | v1 只内置；无 services/模块 HTTP |
| 审计哈希成本 | 服务端代算；A 纯 JS 限频 |
| 前端手写复杂度 | M1 原型；失败换轻量框架/Canvas |
| 发布范围回退 | 检查单禁止多服/分布式代码 |

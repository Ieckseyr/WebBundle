# WebBundle 数据模型与 v1 存储

> 状态：v1.3（两种网页形态；离线查看属于单独挂载网页端）
> 上游：[00 v1 范围与探针](00-v1范围与运行时探针.md) / [01 总体架构](01-总体架构与设计决策.md) / [02 插件层](02-插件层与链入API.md) / [07 单独挂载网页端](07-单独挂载网页端与离线修改.md)
> v1 有两套存储，职责不同：
> - **形态 A**：插件进程内热缓存 + 本地 RocksDB 侧车 / LevelDB；只服务 BDS 运行时的内置网页。
> - **形态 B**：单独挂载的 `webbundle-web` 自有数据库；接收插件推送；BDS 停止后提供冷查看。
> **Redis/MongoDB/Cassandra/Kafka/Parquet 是 v2，见 [06](06-v2-外部模式与分布式.md)。**

---

## 1. 存储映射

| 形态 | 热层 | 温层 | 日志 | 网页 |
|---|---|---|---|---|
| A 内置 | 插件进程 `Map` | 本地 RocksDB 侧车 / LevelDB 分块 | 本地事件列族 | 插件 `HttpServer` |
| B 单独挂载 | `webbundle-web` 进程 `Map` | `webbundle-web` 自有 SQLite/RocksDB | 自有事件表/列族 | `webbundle-web` |

- 形态 A 没有冷查看：BDS 停止，进程消失。
- 形态 B 才有冷查看：`webbundle-web` 独立运行，读自己的库。
- 未部署形态 B：BDS 停止后没有网页可用，这是预期边界。

---

## 2. 数据模型

所有时间戳 Unix 毫秒；物品类型带 `minecraft:`；ID 为 UTF-8。

### 2.1 ItemStack

```json
{
  "t": "minecraft:diamond_sword",
  "c": 1,
  "a": 0,
  "n": "§6耐久之刃",
  "l": ["第一行描述"],
  "e": [[9, 5], [17, 3]],
  "d": 12,
  "h": "6f3a1c2b9d4e8f70",
  "nbt": "{display:{Name:'...'}}",
  "nbtRef": null,
  "nbtSize": 42,
  "nbtOmitted": false
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `t` | string | 物品类型 |
| `c` | uint32 | 数量 1..255 |
| `a` | sint32 | aux |
| `n` | string | 自定义名 |
| `l` | string[] | lore |
| `e` | [int,int][] | 附魔 |
| `d` | sint32 | 耐久损耗 |
| `h` | string | NBT 摘要（FNV-1a 64） |
| `nbt` | string | 小 NBT 的 SNBT；null 表示未内联 |
| `nbtRef` | string | 大 NBT 引用；与 `nbt` 二选一 |
| `nbtSize` | uint32 | NBT 字节数 |
| `nbtOmitted` | bool | 超限未内联；不伪造完整 |

小 NBT 阈值默认 64KB；单物品 512KB；单备份 8MB；超限走 ref 或 `nbtOmitted`。

### 2.2 InventorySnapshot

```json
{
  "schema": 1,
  "id": "srv-1:2535...:1024",
  "serverId": "srv-1",
  "xuid": "2535416158535227",
  "uuid": "2a30fa4a-3a63-3370-88a8-144a941101e2",
  "name": "Steve",
  "seq": 1024,
  "ts": 1730000000000,
  "minute": 28833333,
  "reason": "minute",
  "hash": "fnv1a64:9a3c...",
  "dim": 0,
  "pos": { "x": 128.5, "y": 64.0, "z": -32.5 },
  "inventory": [{ "slot": 0, "item": { "t": "minecraft:stone", "c": 64 } }],
  "armor": [],
  "offhand": [],
  "ender": [],
  "meta": { "level": 30, "gameMode": "survival" },
  "prevId": null
}
```

- 只存占用槽位。
- `uuid` 用于离线 NBT 读写。
- `slot` 主背包 0–35、盔甲 0–3、副手 0、末影箱 0–26，以 `SLOT_LAYOUT` 为单一来源。
- `hash` FNV-1a 64；相同可写引用。
- `reason`：`minute | join | leave | manual | pre-restore | drift | pre-edit`。
- `prevId` 引用链上限 64。
- `schema` 兼容 `<= 当前版本`。

### 2.3 InventoryDelta

```json
{
  "schema": 1,
  "serverId": "srv-1",
  "xuid": "2535...",
  "seq": 1025,
  "ts": 1730000000123,
  "baseSeq": 1024,
  "changes": [
    { "container": "inventory", "slot": 12, "item": null },
    { "container": "inventory", "slot": 13, "item": { "t": "minecraft:diamond", "c": 3 } }
  ]
}
```

只用于实时视图/模块事件；长期历史用分钟备份。

### 2.4 FlowEvent

```json
{
  "schema": 1,
  "id": "srv-1:000000000123",
  "ts": 1730000000000,
  "serverId": "srv-1",
  "xuid": "2535...",
  "name": "Steve",
  "kind": "drop",
  "direction": "out",
  "item": { "t": "minecraft:diamond", "a": 0, "h": null },
  "count": 1,
  "slot": 12,
  "container": "inventory",
  "pos": { "x": 128.5, "y": 64.0, "z": -32.5 },
  "dim": 0,
  "before": 64,
  "after": 63,
  "ref": "drop:entity:123",
  "txId": null,
  "confidence": 1.0,
  "traceId": "b7c3..."
}
```

- `id` 的 `seq` 是服务器级事件序号，与玩家备份 `seq` 分开。
- v1 完整归因 drop/pickup；craft 实验性；其他 `unknown`。
- 同一 `eventId` 只入账一次。

### 2.5 Task

```json
{
  "schema": 1,
  "taskId": "01J...",
  "kind": "command" | "action",
  "actionId": "inventory.restore",
  "state": "queued" | "queued_offline" | "running" | "succeeded" | "failed" | "canceled" | "expired",
  "operator": { "name": "admin", "role": "admin", "ip": "10.0.0.5" },
  "input": {},
  "result": {},
  "error": null,
  "createdAt": 1730000000000,
  "startedAt": null,
  "finishedAt": null,
  "traceId": "b7c3..."
}
```

`queued_offline` 只存在于形态 B（单独挂载网页端），开服后由插件拉取执行。

### 2.6 AuditRecord

```json
{
  "schema": 1,
  "seq": 88421,
  "ts": 1730000000000,
  "serverId": "srv-1",
  "operator": "admin",
  "ip": "10.0.0.5",
  "action": "command.execute",
  "target": { "xuid": "2535...", "taskId": "01J..." },
  "inputHash": "sha256:...",
  "result": "ok",
  "detail": "give Steve minecraft:diamond 1",
  "prevHash": "sha256:...",
  "hash": "sha256:..."
}
```

审计只追加；`hash = SHA256(canonical + prevHash)`。形态 A 用纯 JS 降级（限频），形态 B 由服务端代算；单队列串行。

## 3. 热层

### 3.1 插件进程内（形态 A）

```js
const hot = new Map(); // xuid -> PlayerState
```

`PlayerState`：`xuid/uuid/name/seq/version/slots/hash/dirty/lastSeen/pos/dim/view`。

- 在线常驻；离线 10 分钟淘汰；最多 2000；`view` 按 version 缓存。
- 读接口返回冻结视图/副本。
- 定时器统一调度，不按玩家建。

### 3.2 webbundle-web 进程内（形态 B）

- `webbundle-web` 自己维护最近备份/查询缓存；数据来自插件推送。
- 缓存只影响读性能，不改变“最后数据”的语义。
- BDS 停止后不再有新推送，缓存/库保持不变。

### 3.3 一致性

- 热层是当前视图的近似；崩溃可能丢最后几百毫秒。
- 形态 A 本地温层是权威历史；形态 B 的库是权威历史。
- 写热层先于写温层；温层失败标 `persist_pending`，页面提示“未落库”。

## 4. 本地温层（形态 A）

### 4.1 RocksDB 侧车（推荐）

插件可配本地 `webbundle-store` 侧车（独立进程，回环 HTTP），或直接用 LSE `KVDatabase`。

列族：

| 列族 | 键 | 值 | 说明 |
|---|---|---|---|
| `meta` | `schema/server/seq` | UTF-8/varint | 元数据 |
| `player` | `p/<xuid>` | PlayerMeta | uuid/name/最后在线/latest |
| `nbt` | `n/<hash>` | ZSTD(SNBT) | 大 NBT 去重 |
| `snapshot` | `s/<xuid>/<seq:u64be>` | ZSTD(Protobuf) | 完整备份 |
| `minute` | `m/<xuid>/<minute:u64be>` | MinuteRef | 分钟桶；只放数值 |
| `manual` | `x/<xuid>/<taskId>` | MinuteRef | 手动备份；独立列族 |
| `event` | `e/<ts:u64be>/<seq:u64be>` | ZSTD(FlowEvent) | 事件 |
| `idx_item` | `i/<itemKey>/<ts>/<seq>` | event seq | 按物品 |
| `idx_player` | `u/<xuid>/<ts>/<seq>` | event seq | 按玩家 |
| `task` | `t/<taskId>` | Task | 动作/命令 |
| `audit` | `a/<ts>/<seq>` | AuditRecord | 审计 |
| `agg` | `g/<scope>/<bucket>/<key>` | Counter | 汇总 |
| `kv` | `k/<module>/<key>` | bytes | 模块 KV |
| `spool` | `s2/<ts>/<seq>` | bytes | 推送失败暂存 |

数值键大端序；手动备份与分钟桶分列族，避免混排序。

写入/读取规则：

- 备份 `(xuid,seq)` 幂等；分钟 `(xuid,minute)` 幂等；手动 `(xuid,taskId)` 幂等。
- 事件按 `eventId` 幂等；批量 ≤64 备份/512 事件。
- 最新备份通过 `p/<xuid>` 定位。
- 前缀扫描必须 `limit` + 超时；禁止全表 `listKey()`。
- 读不触发 compaction。

RocksDB 参数：write buffer 64MB、max background 4、ZSTD、block cache 128MB、bloom 10 bits。

### 4.2 LevelDB 降级（形态 A）

`KVDatabase` 只有精确键 + `listKey()`；Lite 用分块索引，不扫全量：

```
bl:players                 xuid 数组（≤50）
bl:p/<xuid>                玩家元数据
bl:ix/<xuid>/<chunk>       256 条分钟引用/块
bl:s/<xuid>/<seq>          备份 JSON
bl:m/<xuid>/<minute>       分钟引用
bl:agg/...                 汇总
```

- 启动只读 `bl:players` + `bl:p` + 最新块；不 `listKey()`。
- 默认保留 7 天；分页每页 ≤50，最多跨 2 块。
- 深历史不可用；Lite 不支持冷查看。

### 4.3 外部网页端数据库（形态 B）

`webbundle-web` 自己选：

- SQLite：单机默认；表 `snapshots/flow/tasks/audit/players/nbt`；索引 `(xuid,ts)`、`(itemKey,ts)`。
- RocksDB：高性能单机；列族与 §4.1 类似。
- MongoDB：v2 多机。

关键：**它不依赖 BDS 进程**；BDS 停止后仍可查询。

## 5. 推送与冷查看

### 5.1 推送

插件 → `webbundle-web`：

```
register/actions/player/snapshot/delta/flow/audit/heartbeat
```

- 批量 ≤200 或 64KB；`lastAckSeq` 续传；`id` 幂等。
- 失败进插件 spool；恢复补写。
- 未配置 `webbundle-web`：不推送，也没有冷查看。

### 5.2 冷查看

- `webbundle-web` 读自己的库；`server.online=false`、`dataAsOf`、`mode=cold`。
- 最后备份/备份/NBT/物品去向/审计。
- 写动作 `queued_offline`；开服后插件拉取。
- 不伪造实时；最后几十秒未推送的增量可能丢失，以最后备份为准。

### 5.3 未部署边界

- 没有 `webbundle-web`：BDS 停止后无网页；这是预期，不是降级。
- 插件 local store 仍然保留历史；可在下次启动时继续用形态 A 查看，或未来导入 B。

## 6. 读写路径

### 6.1 写路径（形态 A）

```
事件 → 影子 → 合并队列 → 热层
  → 本地温层（异步批量）
  → 分钟备份
  → 审计单队列
```

### 6.2 写路径（形态 B）

```
事件 → 影子 → 合并队列 → 热层
  → 推送队列 → webbundle-web 自有库
  → 分钟备份（同时推送）
  → 审计（服务端哈希）
```

### 6.3 读路径

形态 A：

```
浏览器 → 插件 HttpServer → 热层/本地温层 → 返回
BDS 停止：网页不可用
```

形态 B：

```
浏览器 → webbundle-web → 自有库 → 返回
BDS 停止：仍可读最后数据
```

历史/事件/汇总查询均走索引/游标；NBT 小内联/大 ref。

### 6.4 一致性

| 场景 | 保证 |
|---|---|
| 热层 | 最终一致；崩溃丢最后几百毫秒 |
| 备份 | `(xuid,seq)` 幂等；分钟最新哈希 |
| 事件 | 至少一次；`eventId` 幂等 |
| 汇总 | 可由事件重算；`asOf` |
| 审计 | 强追加；单队列；失败告警 |
| 推送 | `lastAckSeq` 续传；重复幂等 |

### 6.5 重启恢复

- 形态 A：侧车/LevelDB 启动；插件读最新备份 + 全量种子；检查审计；
- 形态 B：`webbundle-web` 独立启动；插件恢复后按 `lastAckSeq` 续传；
- `queued_offline` 保留，开服后执行。

## 7. 分钟备份、保留与恢复

### 7.1 分钟桶语义

- 桶 = 该分钟内某一时刻的备份，不是分钟结束状态。
- 跨分钟边界在线的玩家每分钟一个桶；内容未变写 `dedup=true` 引用。
- 同一分钟重复触发幂等。
- 崩溃不补历史桶。
- 进服/退服用 `reason=join/leave` 单独记录，不占分钟桶。
- 短会话不强行造桶。
- 手动备份 `reason=manual`，`manual` 列族，不占分钟桶。
- 引用链上限 64。

### 7.2 键

```
minute: m/<xuid>/<minute:u64be>
manual: x/<xuid>/<taskId>
snapshot: s/<xuid>/<seq>
nbt: n/<hash>
```

### 7.3 保留

| 数据 | 形态 A | 形态 B | 清理 |
|---|---|---|---|
| 分钟引用 | 30 天 | 30 天 | 玩家索引 + 分钟前缀；Lite 整块 |
| 备份载荷 | 同引用 | 同引用 | 引用计数；0 引用 7 天后删 |
| 手动 | 90 天 | 90 天 | manual 分页 |
| 事件 | 30 天 | 30 天 | 按 ts 前缀 |
| 汇总 | 365 天 | 365 天 | 按桶 |
| 任务 | 7 天 | 7 天 | createdAt |
| 审计 | 180 天 | 180 天 | 归档后 |

清理分批 ≤200、可中断、可观测；遍历玩家索引，不扫全键空间。

### 7.4 恢复

- 在线：`Player.getInventory()/getArmor()/getOffHand()/getEnderChest()`。
- 离线（BDS 开）：`data.xuid2uuid` → `mc.getPlayerNbt` → 改背包标签 → `mc.setPlayerNbtTags`。
- BDS 关：形态 B 队列 `queued_offline`，开服后执行。
- pre-restore 备份、校验 hash/schema、替换/合并、重读、审计。
- v1 默认恢复 inventory/armor/offhand；ender 显式选择。

## 8. 容量与性能

### 8.1 容量（100 在线/30 天）

| 项 | 估算 |
|---|---|
| 分钟引用 | ~207MB |
| 变化备份 | ~2.6GB |
| 事件 | ~5.2GB |
| NBT 内联/大对象 | ~1.5–5GB |
| 审计/汇总 | ~50MB |
| 合计 | ~10–15GB/月 |

NBT 是最大变量：统计带 NBT 物品比例/大小；大 NBT 走 ref 去重。

### 8.2 性能预算

| 操作 | 目标 |
|---|---|
| 事件回调 | p99 ≤50µs |
| 合并 flush | p99 ≤2ms |
| 分钟备份单玩家 | p99 ≤2ms（不含大 NBT） |
| 备份批量 | 8 人/tick，≤0.3ms |
| 热层读 | p99 ≤1ms |
| 温层点查 | p99 ≤5ms |
| 前缀页 | p99 ≤20ms |
| NBT 单物品读取 | p99 ≤5ms |
| NBT SNBT | p99 ≤10ms/物品 |
| 形态 A 内置 Web | p95 ≤10ms（探针 A 约束） |
| 形态 B 冷查看首屏 | p95 ≤300ms |
| 离线 NBT 写入 | p99 ≤50ms |

### 8.3 告警

- 备份落后 >2 分钟；
- 推送队列 >1000；
- 审计断链/积压；
- 磁盘 <15%；
- 离线任务失败率 >5%。

## 9. Schema 演进

- 数据 `schema` 从 1；配置 `_config_version` 从 1；模块 `api` 独立。
- Protobuf 只追加字段；删除保留 tag/`reserved`；未知枚举按 UNKNOWN。
- 迁移前备份；迁移脚本通过 HTTP/CLI 读写，可重入；失败回滚。
- 形态 A/B 的 schema 各自迁移；推送契约版本独立。

## 10. 降级与故障

| 故障 | 形态 A | 形态 B | 数据 |
|---|---|---|---|
| BDS 停止 | 网页不可用 | 冷查看 | 最后备份 |
| 未部署 B | 正常 | 无离线查看 | 仅本地 |
| B 停止 | 正常 | 网页不可用 | 插件 spool |
| 本地侧车未启动 | 用 LevelDB/内存 | 不受影响 | 本地 |
| 磁盘满 | 停止写，保留读 | 停止写 | 告警/清理 |
| 离线 NBT 写入失败 | — | 任务失败 | pre-edit 回滚 |
| 玩家在离线写入期间进服 | — | 任务失败/转在线 | 不覆盖在线 |
| 推送失败 | 正常 | 数据滞后 | spool 重试 |

## 11. 安全

- 本地侧车只监听回环；如非回环启用 token/TLS。
- `webbundle-web` 强制 HTTPS；`pushToken` 与 Web 令牌分离。
- NBT 可能含敏感文本；按 `inventory.read`，不写日志。
- 离线修改：`inventory.write` + 确认 + pre-edit 备份 + 审计；默认 admin。
- 冷查看也鉴权；不因 BDS 停止放宽。
- 不直接暴露世界存档；网页端只读写自己的库。

## 12. 验收

- [ ] 形态 A：内置网页在 BDS 运行时可用；BDS 停止后不可用。
- [ ] 形态 B：未部署时 BDS 停止后无网页；部署后冷查看可用。
- [ ] 分钟桶语义/幂等/不补历史；join/leave 单独记录。
- [ ] 内容未变写引用；引用链可解析；手动备份独立列族。
- [ ] 事件 `eventId` 幂等；查询走索引/游标。
- [ ] 完整 NBT 小内联/大 ref；超限不截断。
- [ ] 在线/离线修改；BDS 关闭时形态 B 队列；开服执行。
- [ ] 操作记录链可校验；断链/积压告警。
- [ ] 推送断档按 `lastAckSeq` 续传；重复幂等。

## 附录 A：Protobuf 定义（v1 草案）

```proto
syntax = "proto3";
package webbundle.v1;

message Enchantment { uint32 id = 1; uint32 level = 2; }

message ItemStack {
  string type = 1;
  uint32 count = 2;
  sint32 aux = 3;
  string custom_name = 4;
  repeated string lore = 5;
  repeated Enchantment enchants = 6;
  sint32 damage = 7;
  bytes nbt = 8;
  string nbt_hash = 9;
  string nbt_ref = 10;
  uint32 nbt_size = 11;
  bool nbt_omitted = 12;
}

message Slot { uint32 index = 1; ItemStack item = 2; }
message Position { double x = 1; double y = 2; double z = 3; }

message InventorySnapshot {
  uint32 schema = 1;
  string id = 2;
  string server_id = 3;
  string xuid = 4;
  string name = 5;
  uint64 seq = 6;
  int64 ts_ms = 7;
  uint64 minute = 8;
  string reason = 9;
  string hash = 10;
  int32 dim = 11;
  Position pos = 12;
  repeated Slot inventory = 13;
  repeated Slot armor = 14;
  repeated Slot offhand = 15;
  repeated Slot ender = 16;
  map<string, string> meta = 17;
  string prev_id = 18;
  string uuid = 19;
}

message MinuteRef {
  string snapshot_id = 1;
  string hash = 2;
  bool dedup = 3;
  string reason = 4;
  int64 written_at_ms = 5;
}

message PlayerMeta {
  string xuid = 1;
  string name = 2;
  int64 first_seen_ms = 3;
  int64 last_seen_ms = 4;
  uint64 latest_seq = 5;
  uint64 latest_minute = 6;
  string uuid = 7;
}

message FlowEvent {
  uint32 schema = 1;
  string id = 2;
  int64 ts_ms = 3;
  string server_id = 4;
  string xuid = 5;
  string name = 6;
  string kind = 7;
  string direction = 8;
  ItemStack item = 9;
  uint32 count = 10;
  int32 slot = 11;
  string container = 12;
  Position pos = 13;
  int32 dim = 14;
  int64 before = 15;
  int64 after = 16;
  string ref = 17;
  string tx_id = 18;
  double confidence = 19;
  string trace_id = 20;
}

message Task {
  uint32 schema = 1;
  string task_id = 2;
  string kind = 3;
  string action_id = 4;
  string state = 5;
  string operator_name = 6;
  string operator_role = 7;
  string operator_ip = 8;
  bytes input_json = 9;
  bytes result_json = 10;
  string error = 11;
  int64 created_at_ms = 12;
  int64 started_at_ms = 13;
  int64 finished_at_ms = 14;
  string trace_id = 15;
}

message AuditRecord {
  uint32 schema = 1;
  uint64 seq = 2;
  int64 ts_ms = 3;
  string server_id = 4;
  string operator_name = 5;
  string operator_ip = 6;
  string action = 7;
  bytes target_json = 8;
  string input_hash = 9;
  string result = 10;
  string detail = 11;
  string prev_hash = 12;
  string hash = 13;
}

message Counter { int64 in = 1; int64 out = 2; int64 net = 3; uint64 events = 4; }
```

约定：`nbt` 为 SNBT UTF-8；`nbt_ref` 指向 `n/<hash>`；`meta` 顺序不稳定，哈希前排序；未知字段保留。
